# Windows メールクライアント 要件定義書（v0.1 たたき台）

- 作成日: 2026-11-12
- 著作権者: 発注者（本リポジトリ所有者）
- 開発: Claude（単独）
- ステータス: ドラフト（「9. 未確定事項」の回答後に v1.0 とする）

---

## 1. 概要

### 1.1 目的
Outlook の使いにくさ・広告表示を解消した、**広告ゼロ・軽量・高速**な Windows 用デスクトップメールクライアントを開発する。

### 1.2 利用者
- 主利用者: 発注者本人
- 将来的に一般配布を想定（ITリテラシー中〜上級者向け）
- UI は日本語のみ

### 1.3 基本方針
| 方針 | 内容 |
|---|---|
| 広告・トラッキング | 一切なし。テレメトリ・外部送信も行わない |
| 速度優先 | 数十万通規模でも一覧・検索・起動が重くならないこと |
| ローカルファースト | メールデータはローカルに保持し、オフラインでも閲覧可能 |
| 段階リリース | 「可能な限り早く」使い始められるよう、MVP → 機能追加の順でリリース |

## 2. 動作環境

| 項目 | 要件 |
|---|---|
| OS | Windows 10 / 11（64bit のみ） |
| 必要ランタイム | 自己完結型で配布（.NET ランタイムのインストール不要）。HTML 表示用に WebView2 Runtime（Win10/11 は通常導入済み。未導入時はインストーラーで導入） |
| 権限 | 管理者権限なしでインストール・実行可能（ユーザー単位インストール） |
| 画面 | 一般的な FHD 以上。ダークモード・高DPI最適化・アクセシビリティは現時点で対象外 |

## 3. 対応メールサービス・プロトコル

### 3.1 プロトコル
| 種別 | 対応 |
|---|---|
| 受信 | IMAP4rev1（IDLE / CONDSTORE / QRESYNC 対応で差分同期・プッシュ受信）、POP3 |
| 送信 | SMTP（STARTTLS / SSL/TLS） |
| 暗号化通信 | TLS 1.2 以上必須。平文接続は警告の上で明示許可時のみ |

### 3.2 認証
| 方式 | 用途 |
|---|---|
| OAuth 2.0（PKCE、システムブラウザ経由） | Gmail / Google Workspace、Outlook.com / Microsoft 365 |
| ユーザー名＋パスワード | 一般 IMAP/POP3/SMTP サーバー、プロバイダメール |
| アプリパスワード | iCloud、Yahoo! など OAuth 非対応・2段階認証サービス |

- 資格情報・トークンは **Windows 資格情報マネージャー（DPAPI）** に保存する。

### 3.3 対応サービス（初期の動作確認対象）
- Gmail / Google Workspace
- Outlook.com / Microsoft 365（IMAP/SMTP + OAuth）
- Yahoo!メール、iCloud メール
- 独自ドメイン・社内サーバー・プロバイダメール（汎用 IMAP/POP3/SMTP）
- アカウント追加時の**サーバー設定の自動検出**（Autoconfig / Autodiscover / 主要サービスのプリセット）

### 3.4 対象外（現時点）
- オンプレミス Exchange（EWS / MAPI）※ Exchange Online の EWS は Microsoft により提供終了済み。M365 は IMAP/SMTP + OAuth で対応する。

### 3.5 複数アカウント
- 複数アカウントの同時利用に対応
- 全アカウント横断の「統合受信トレイ」を提供

## 4. 機能要件

優先度: **P1 = MVP（初回リリース）**、**P2 = 第2弾**、**P3 = 第3弾**

### 4.1 基本メール機能
| ID | 機能 | 優先度 |
|---|---|---|
| F-01 | メールの受信、送信、返信、全員に返信、転送 | P1 |
| F-02 | 添付ファイルの送受信、保存、ドラッグ＆ドロップでの添付 | P1 |
| F-03 | 添付ファイルのプレビュー（画像、PDF、テキスト） | P2 |
| F-04 | HTML メールの表示（**外部画像は既定でブロック**、スクリプトは常に無効） | P1 |
| F-05 | テキスト形式と HTML 形式でのメール作成（HTML は簡易リッチエディタ） | P1 |
| F-06 | フォルダの作成・名前変更・削除、メールの移動、削除、ゴミ箱 | P1 |
| F-07 | 下書きの自動保存（ローカル保存＋サーバーの下書きフォルダへ同期） | P1 |
| F-08 | 署名（アカウントごとに複数登録可、自動挿入） | P1 |
| F-09 | 既読・未読、フラグ（重要）、ラベル（Gmail ラベル／IMAP キーワード） | P1 |
| F-10 | スレッド（会話）表示と通常表示の切り替え | P2 |

### 4.2 検索

|---|---|---|

| S-03 | 条件指定検索（期間、添付ファイルの有無、フォルダ、アカウント） | P2 |
| S-04 | 検索条件の保存（スマートフォルダ） | P3 |

### 4.3 連絡先

|---|---|---|
| C-01 | アドレス帳（登録、編集、グループ） | P1 |

### 4.4 整理・自動化

| A-02 | 迷惑メール判定（サーバー判定の尊重＋ローカル学習型フィルタ） | P2 |

| A-04 | テンプレート（定型文） | P2 |

### 4.5 通知
| ID | 機能 | 優先度 |
|---|---|---|
| N-01 | 新着通知（Windows トースト通知）、タスクトレイ常駐、未読バッジ | P1 |

### 4.6 誤送信対策
| ID | 機能 | 優先度 |
|---|---|---|

## 5. 非機能要件

### 5.1 性能目標
| 項目 | 目標値 |
|---|---|
| 起動時間（コールドスタート） | 2秒以内にメール一覧を表示 |
| メール一覧のスクロール | 10万通以上のフォルダでも引っかかりなし（仮想化表示） |
| フォルダ切り替え | 300ms 以内 |
| 全文検索 | 50万通で1秒以内 |
| メモリ使用量 | 通常時 300MB 以下を目安 |
| 同期 | 差分同期（CONDSTORE/QRESYNC）、IDLE によるプッシュ受信。初回同期はヘッダーを優先して取得し、本文は後から取得 |

### 5.2 文字コード・メール形式
- UTF-8、**ISO-2022-JP（JIS）、Shift_JIS、EUC-JP** の正しいデコード
- 機種依存文字（丸数字、①、㈱ など）を含む ISO-2022-JP メールの文字化け対策
- 送信時の文字コードは既定 UTF-8（アカウントごとに ISO-2022-JP も選択可）
- MIME エンコードされたヘッダー・添付ファイル名（RFC 2047 / 2231）、壊れたメールにも寛容に対応

### 5.3 セキュリティ
- 資格情報は資格情報マネージャー（DPAPI）に保存し、平文では保存しない
- HTML メールはサンドボックス化した WebView で表示する（スクリプト無効、外部リソースは既定でブロック）
- TLS 証明書を検証し、不正な証明書の場合は警告する
- 外部へのテレメトリ・ログ送信は行わない（エラーログはローカルにのみ保存）

### 5.4 信頼性
- ローカル DB はトランザクション管理（WAL モード）で、異常終了時も破損しない
- サーバーとローカルの不整合を検出した際は自動で再同期する

### 5.5 保守性
- メール処理ロジックと UI を分離し、ロジックは自動テストで検証する
- 文字コードについてはテスト用のメールコーパスで回帰テストを行う

## 6. 技術構成（案）

| 領域 | 採用技術 | 理由 |
|---|---|---|
| 言語・ランタイム | C# / .NET 10（LTS） | Windows ネイティブ、高速、長期サポート |
| UI | WPF | 実績があり、大量データの仮想化表示が安定している |
| メールプロトコル・MIME | MailKit / MimeKit（MIT） | IMAP/POP3/SMTP/OAuth/S/MIME/PGP を網羅し、日本語文字コードにも強い |
| ローカル DB・検索 | SQLite（WAL）＋ FTS5（日本語は N-gram でトークン化） | 軽量、高速、単一ファイルでバックアップしやすい |
| メール本文の保存 | 1通ごとに .eml ファイル＋ DB にインデックス | 破損に強く、エクスポートが容易 |
| HTML 表示 | WebView2 | Chromium ベースで表示が正確、サンドボックス化できる |
| 資格情報 | Windows 資格情報マネージャー（DPAPI） | OS 標準の安全な保管場所 |
| 通知 | Windows App SDK のトースト通知 | OS 標準 |
| インストーラー・自動更新 | Velopack（MIT） | setup.exe 生成、管理者権限不要のユーザー単位インストール、差分アップデートに対応 |
| 配布元 | GitHub Releases（案） | 無料で、自動更新の配信元としても使える |

- 依存ライブラリは MIT / Apache 2.0 など**著作権表示のみで利用可能なライセンスに限定**し、GPL 系は使用しない（発注者の著作権・配布の自由度を確保するため）。

## 7. 配布・運用

| 項目 | 内容 |
|---|---|
| 形式 | setup.exe（ユーザー単位インストール、管理者権限不要） |
| アンインストール | Windows の「アプリと機能」から実行可能 |
| コード署名 | なし（予定なし） → **初回実行時に SmartScreen の警告「WindowsによってPCが保護されました」が表示される**。「詳細情報」→「実行」で起動できる旨を配布ページに明記する |
| 自動更新 | Velopack による更新確認と差分更新 |
| ログ | ローカルにのみ保存（不具合調査時に利用者が手動で提供） |

## 8. 開発計画（案）

| フェーズ | 内容 | 主な対象 |
|---|---|---|
| Phase 0 | 基盤 | プロジェクト構成、DB、同期エンジン、文字コードのテスト、インストーラー・自動更新の仕組み |
| Phase 1（MVP） | 日常的に使える最小構成 | 全 P1 機能（IMAP/POP3/SMTP、OAuth、送受信、検索、誤送信対策、通知、オフライン） |
| Phase 2 | 快適化 | スレッド表示、振り分けルール、迷惑メール判定、予約送信、テンプレート、バックアップ、インポート／エクスポート、招待状への返信 |
| Phase 3 | 拡張 | S/MIME・PGP、カレンダー、タスク、連絡先同期、.pst インポート |

※ 期間の見積もりは、未確定事項の確定後に提示する。

## 9. 未確定事項（発注者への確認事項）

| No | 確認事項 | 補足・提案 |
|---|---|---|
| Q1 | 「クラウドに保存」の具体的な意味 | (a) 設定・メールのバックアップを OneDrive / Google Drive / Dropbox などに保存する、(b) 複数 PC 間で設定を同期する、(c) データフォルダ自体をクラウドに置く、のいずれか。**(a) を推奨**。(c) は同期ソフトと DB の競合で破損するリスクがあるため非推奨 |
| Q2 | Gmail の OAuth と一般配布 | Gmail をメールアクセス権限付きで**一般配布**する場合、Google による審査（セキュリティ評価 CASA。年1回、有償の場合あり）が必要になる。審査なしでは「テストユーザー」100人までに制限される。当面は自分用＋少人数で運用し、本格配布時に審査を受ける方針でよいか |
| Q3 | Microsoft 365 の OAuth 登録 | Microsoft Entra ID（旧 Azure AD）へのアプリ登録が必要（無料）。発注者の Microsoft アカウントで登録してよいか |
| Q4 | 配布元 | GitHub Releases（リポジトリを公開する必要があるか、配布用の公開リポジトリを別に作るか）または独自 Web サイト |
| Q5 | アプリ名 | 正式名称（インストーラー、ウィンドウタイトル、データフォルダ名に使用） |
| Q6 | 受信間隔・保持期間の既定値 | IDLE 非対応サーバーでの確認間隔（既定5分を想定）、POP3 でのサーバー上のメールの残し方 |
| Q7 | UI レイアウト | 3ペイン（フォルダ／一覧／本文）横並びを既定とし、プレビューを下に表示する配置にも切り替え可能、でよいか |
| Q8 | 予約送信の仕様 | アプリ終了中は送信されない仕様でよいか（サーバー側の予約送信は Gmail / M365 の独自機能のため、汎用には実装できない） |
